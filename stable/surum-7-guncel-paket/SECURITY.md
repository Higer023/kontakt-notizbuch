# Security Policy

Thank you for helping keep Kontakt-Notizbuch and its users safe. This project may handle sensitive contact information; please treat reports carefully.

## Supported versions
Security fixes target the current `main` branch. Snapshots under `stable/` are historical and are not guaranteed to receive fixes.

## Report a vulnerability privately
Do not publish exploitable details, personal data, credentials, or live reproduction steps in a public issue. Use GitHub's private vulnerability reporting or Security Advisories feature for this repository when available. Include the affected path/endpoint, impact, prerequisites, and a minimal reproduction using synthetic data only.

Never include real contact records, production tokens, passwords, recovery codes, or encryption keys. If a credential may have been exposed, revoke or rotate it promptly. Please allow maintainers reasonable time to investigate before public disclosure.

## Scope and limitations
A passing CI run is not a security certification. Authentication, WebAuthn/passkeys, encryption, recovery, migrations, authorization boundaries, and backup restoration require careful review before production use.

# Güvenlik Politikası

Kontakt-Notizbuch'u ve kullanıcılarını güvende tutmaya yardımcı olduğunuz için teşekkürler. Proje hassas iletişim bilgileri işleyebilir; güvenlik bildirimlerini dikkatle ele alın.

## Desteklenen sürümler
Güvenlik düzeltmeleri mevcut `main` dalını hedefler. `stable/` altındaki kopyalar geçmiş sürümlerdir; güvenlik güncellemesi alacakları garanti edilmez.

## Güvenlik açığını özel olarak bildirin
İstismar edilebilir ayrıntıları, kişisel verileri, kimlik bilgilerini veya çalışan bir açığın yeniden üretim adımlarını herkese açık issue'larda yayımlamayın. Depo için kullanılabiliyorsa GitHub'ın özel güvenlik açığı bildirimi veya Security Advisories özelliğini kullanın. Etkilenen dosya/yol veya uç noktayı, etkiyi, ön koşulları ve yalnızca sentetik veri kullanan asgari bir örneği ekleyin.

Gerçek kişi kayıtlarını, üretim tokenlarını, parolaları, kurtarma kodlarını veya şifreleme anahtarlarını eklemeyin. Bir kimlik bilgisinin açığa çıkmış olabileceğini düşünüyorsanız onu derhâl iptal edin veya yenileyin. Herkese açıklamadan önce bakımcılara inceleme için makul süre tanıyın.

## Kapsam ve sınırlamalar
CI testlerinin geçmesi güvenlik sertifikası değildir. Kimlik doğrulama, WebAuthn/passkey, şifreleme, kurtarma, veri geçişleri, yetki sınırları ve yedekten geri yükleme üretimde kullanımdan önce dikkatle incelenmelidir.

# Sicherheitsrichtlinie

Vielen Dank, dass Sie helfen, Kontakt-Notizbuch und seine Nutzer:innen zu schützen. Das Projekt kann sensible Kontaktdaten verarbeiten; bitte behandeln Sie Meldungen entsprechend sorgfältig.

## Unterstützte Versionen
Sicherheitskorrekturen zielen auf den aktuellen Branch `main`. Kopien unter `stable/` sind historische Stände; Sicherheitsupdates werden dafür nicht garantiert.

## Sicherheitslücke vertraulich melden
Veröffentlichen Sie keine ausnutzbaren Details, personenbezogenen Daten, Zugangsdaten oder reproduzierbaren Schritte zu einer aktiven Schwachstelle in öffentlichen Issues. Nutzen Sie, sofern verfügbar, GitHubs vertrauliche Sicherheitsmeldung oder Security Advisories für dieses Repository. Nennen Sie betroffenen Pfad/Endpunkt, Auswirkungen, Voraussetzungen und eine minimale Reproduktion ausschließlich mit synthetischen Daten.

Fügen Sie niemals echte Kontaktdaten, Produktions-Tokens, Passwörter, Wiederherstellungscodes oder Verschlüsselungsschlüssel bei. Widerrufen oder erneuern Sie möglicherweise offengelegte Zugangsdaten umgehend. Geben Sie den Maintainer:innen vor einer Veröffentlichung angemessene Zeit zur Prüfung.

## Umfang und Grenzen
Erfolgreiche CI-Tests sind keine Sicherheitszertifizierung. Authentifizierung, WebAuthn/Passkeys, Verschlüsselung, Wiederherstellung, Migrationen, Berechtigungsgrenzen und Backup-Wiederherstellung müssen vor dem Produktiveinsatz sorgfältig geprüft werden.
